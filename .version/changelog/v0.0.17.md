# [v0.0.17] - 2026-10-20

## 新增

- ACP (Agent Client Protocol) 接入:`fastgit` 作为 ACP client spawn 外部 agent 进程生成 commit message(spawn → initialize → session/new → session/prompt,收集 agent_message;agent 权限请求自动拒绝;超时与进程清理内置)
- `ggc acp` 管理命令:`list`(配置 + 内置 catalog 状态)、`add <name> [--command X --args "a b" --env K=V]`、`remove <name>`、`set-default <name>|--clear`、`test [name] [--prompt] [--timeout 秒]`
- 配置文件新增 `acp:` 段(`default` + `agents.<name>.command/args/env`)与 `ai:` 段(`provider`:auto|acp|openai|copilot)
- 内置 ACP agent catalog:claude(`npx @zed-industries/claude-code-acp`)、codex、gemini、opencode,可直接 `ggc acp add <name>` 引用
- 环境变量 `FASTGIT_ACP_AGENT` 临时覆盖选用的 agent;`FASTGIT_AI_PROVIDER` 临时覆盖 provider

## 变更

- `acp-go-sdk` 升级 v0.6.3 → v0.13.5(适配 `KillTerminalRequest`、`ToolCallUpdate` 等协议改名)
- AI provider 默认链(auto)变为 acp → openai → copilot → 规则;openai 不再是首选但保留为可选 provider
- `tag` 命令移除未使用的 OpenAI client 注入字段

## 影响范围

- 配置了 ACP agent 后,commit/review/pr/conflict 的 AI 默认走 ACP;未配置时行为与旧版一致(openai → copilot → 规则)
- provider 选择可通过 `--ai*` flag、`FASTGIT_AI_PROVIDER`、`ai.provider` 逐级覆盖

## 验证建议

- `ggc acp list` / `ggc acp test <name>` 验证 agent 连通;在任意仓库跑 `ggc commit ai` 确认 message 由 ACP agent 生成

## 回滚建议

- 设置 `ai.provider: openai` 即可恢复旧 provider 链;代码层回退本次提交
